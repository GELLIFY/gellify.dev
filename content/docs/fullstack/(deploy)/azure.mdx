## Azure Deployment Guide

This template includes Azure scaffolding for future enablement. It targets Azure App Service for web app hosting and mirrors the Preview/Production pattern used elsewhere.

### Overview

- Preview: optional job in `deploy-preview.yml` (commented `deploy_azure`) after DB prep
- Production: optional job in `deploy-production.yml` (commented `deploy_azure_production`) gated on CI and migrations
- Cleanup: optional step in `cleanup-preview.yml` to remove preview resources

### Why Azure App Service

- Simple GitHub integration, supports Next.js builds, and works well for company projects that prefer PaaS
- Alternative options: Azure Container Apps/App Service with Docker for containerized apps

### Prerequisites (when enabling)

- Azure subscription and resource group
- An App Service configured for your repo
- GitHub OIDC or a Service Principal for deployment

Recommended Secrets/Variables

- Secrets
  - `AZURE_CLIENT_ID*` or a Service Principal secret
  - `AZURE_TENANT_ID*` or a Service Principal secret
  - Any app secrets required at runtime (e.g., `DATABASE_URL`)
- Variables
  - App names, resource group names, subscription IDs

### Enabling Preview Deployment

In `.github/workflows/deploy-preview.yml`, uncomment the `deploy_azure` job stub.

Inputs to provide (example)

```yaml
with:
  AZURE_CLIENT_ID: ${{ secrets.AZURE_CLIENT_ID }}
  AZURE_TENANT_ID: ${{ secrets.AZURE_TENANT_ID }}
  AZURE_SUBSCRIPTION_ID: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
  DATABASE_URL: ${{ needs.prepare_db.outputs.neon_db_url }}
  NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY: ${{ secrets.NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY }}
```

Notes

- Ensure build/runtime env vars are configured in Azure (App Settings) or passed via the workflow
- For OIDC, use `azure/login` and avoid long-lived secrets

### Enabling Production Deployment

In `.github/workflows/deploy-production.yml`, uncomment the `deploy_azure_production` job.

Inputs to provide (example)

```yaml
with:
  DATABASE_URL: ${{ secrets.DATABASE_URL }}
  NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY: ${{ secrets.NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY }}
```

CI Gate

- Production deploy is gated on the reusable `CI` workflow and on successful DB migrations

### Cleanup on PR Close

In `.github/workflows/cleanup-preview.yml`, uncomment the Azure cleanup step and pass the necessary token.

### Troubleshooting

- Build succeeds locally but fails on Azure: align Node, PNPM versions in the Setup step
- Env variables not present: set them in App Settings or use Key Vault references
- Permissions errors: prefer OIDC with `azure/login@v2` and proper role assignments
